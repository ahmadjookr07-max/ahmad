# دليل التسليم والتشغيل — استوديو صور المتجر 2.9.5

هذا الدليل يشرح **ما تسلّمه**، و**كيف تبني المثبّتين**، و**كيف تشغّل النظام**
بشقيه: برنامج المستخدم (الموظف) وبرنامج المالك (إصدار المفاتيح).

---

## 1. بنية النظام: برنامجان مرتبطان بالتشفير

النظام مكوّن من برنامجين منفصلين تمامًا، يربط بينهما **زوج مفاتيح تشفيري**:

| البرنامج | الملف التنفيذي | لمن | الوظيفة |
| --- | --- | --- | --- |
| **استوديو صور المتجر** | `AhmedAlFaifiStudio.exe` | الموظف / العميل | معالجة صور المنتجات وتجهيزها للمتجر |
| **مركز إدارة التراخيص** | `AhmedAlFaifiOwnerStudio.exe` | المالك فقط | إصدار مفاتيح التفعيل وإلغاؤها ومتابعة العملاء |

### آلية الربط

برنامج المالك يحتفظ بـ**المفاتيح الخاصة** في ملف `owner_secrets.json`،
وبرنامج المستخدم يحمل **المفاتيح العامة** مغروسة داخل كوده. عند إصدار مفتاح:

1. المالك يُدخل بصمة جهاز العميل والمدة، فيوقّع البرنامج المفتاح
   **توقيعًا مزدوجًا**: `Ed25519` التقليدي + `ML-DSA-65` المقاوم للحاسوب الكمي.
2. برنامج المستخدم يتحقق من **التوقيعين معًا** بالمفاتيح العامة المغروسة.
3. إن فشل أي توقيع، أو لم يطابق المفتاح بصمة الجهاز، يُرفض التفعيل.

> **تحذير حاسم:** ملف `owner_secrets.json` هو أصل النظام كله. إن فُقد،
> لن تستطيع إصدار أي مفتاح جديد للنسخ الموزّعة. احفظ منه نسخة احتياطية
> في مكان آمن خارج الجهاز. وهو **مستثنى من المستودع** عن قصد
> (مذكور في `.gitignore`) حتى لا يُسرَّب.

## 2. الفترة التجريبية — كيف تعمل ولماذا لا تُخترق

الفترة التجريبية **ثلاثة أيام** تبدأ تلقائيًا عند أول تشغيل، وتمنح
**كل الميزات بلا استثناء**. حصّنت ضد ثلاث طرق تحايل شائعة:

| المحاولة | النتيجة |
| --- | --- |
| حذف ملف الفترة التجريبية لتصفيرها | يفشل: يوجد أثر ثانوي موازٍ، والنظام يعتمد **التاريخ الأقدم** بين المصدرين |
| إرجاع ساعة النظام للوراء | يُكتشف ويُرفض؛ النظام يسجّل أقصى تاريخ رآه ويقارن به |
| إعادة تثبيت البرنامج | المثبّت **يحفظ بيانات الترخيص** ولا يحذفها إلا بطلب صريح من المالك |

بعد انتهاء الثلاثة أيام، يُغلق البرنامج ميزاته ويطلب مفتاح تفعيل من المالك،
مع عرض بصمة الجهاز لينسخها العميل ويرسلها.

| المدة | القيمة | ملاحظة |

## 4. بناء المثبّتين

### الطريقة الأولى: البناء الآلي عبر GitHub (المُوصى بها)

المستودع يحتوي خط بناء آليًا كاملًا. لتشغيله:

1. افتح المستودع على GitHub ← تبويب **Actions**.
2. اختر **Build Windows (Studio + Owner)** ← **Run workflow**.
3. انتظر انتهاء البناء (نحو 15–25 دقيقة).
4. نزّل الحزمة من قسم **Artifacts**.

خط البناء يفعل التالي بالترتيب، ويتوقف عند أي خلل:

- يتحقق من **صحة الربط** بين البرنامجين (يُصدر مفتاحًا تجريبيًا ويتحقق منه)
- يُشغّل اختبارات الترخيص والفترة التجريبية
- ينزّل نماذج الذكاء الاصطناعي (ISNet + U2Net)
- يبني البرنامجين بـ PyInstaller
- **يفحص تشغيل الملفين التنفيذيين فعليًا** (اختبار ذاتي)
- يبني المثبّتين بـ NSIS

### الطريقة الثانية: البناء المحلي على ويندوز

تحتاج: ويندوز 10 أو أحدث (64-بت)، Python 3.11، و NSIS.

```bat
REM 1) التبعيات
pip install -r requirements.txt pyinstaller

REM 2) توليد شفرة المالك (مرة واحدة فقط في عمر المشروع!)
python tools\generate_owner_secrets.py

REM 3) التحقق من الربط
python tools\verify_owner_link.py

REM 4) بناء البرنامجين
pyinstaller --clean --noconfirm build\windows\AhmedAlFaifiStudio.spec
pyinstaller --clean --noconfirm build\windows\AhmedAlFaifiOwnerStudio.spec

REM 5) بناء المثبّتين
makensis build\windows\installer_v295.nsi
makensis build\windows\installer_owner_v295.nsi
```

الناتج مثبّتان في مجلد `dist`:

- `AhmedAlFaifiStudio_Setup_2.9.5.exe` — يوزَّع على الموظفين
- `AhmedAlFaifiOwnerStudio_Setup_2.9.5.exe` — للمالك فقط

## 5. ترتيب التشغيل الصحيح

اتبع هذا الترتيب حرفيًا في المرة الأولى:

**أولًا: جهاز المالك**

1. ثبّت `AhmedAlFaifiOwnerStudio_Setup_2.9.5.exe`.
2. شغّله؛ سيطلب في أول مرة إنشاء **كلمة مرور المالك** — اخترها قوية.
3. سيولّد شفرة المالك تلقائيًا إن لم تكن موجودة، أو استوردها إن كانت لديك.
4. **خُذ نسخة احتياطية من `owner_secrets.json` فورًا** إلى مكان آمن.

**ثانيًا: جهاز الموظف**

1. ثبّت `AhmedAlFaifiStudio_Setup_2.9.5.exe`.
2. شغّله؛ سيقبل الاتفاقية ثم تبدأ الفترة التجريبية (3 أيام، كل الميزات).
3. عند الحاجة للتفعيل، انسخ **بصمة الجهاز** المعروضة وأرسلها للمالك.

**ثالثًا: إصدار المفتاح**

1. المالك يفتح برنامجه ← يُدخل بصمة الجهاز ← يختار المدة ← يُصدر المفتاح.
2. يرسل المفتاح للموظف، فيلصقه في نافذة التفعيل.
3. يعرض البرنامج المدة المتبقية ويفتح كل الميزات.

## 6. ما تفعله وظائف البرنامج (مُتحقَق منها بالاختبار)

| الوظيفة | التحقق |
| --- | --- |
| **قص الخلفية** | نموذج U2Net/ISNet، ثقة 0.99، قناع بحواف ناعمة |
| **الظل الواقعي** | اتجاه الظل يتبع زاوية الإضاءة فعليًا، وشدته قابلة للضبط |
| **المقاس القياسي** | 800×700 بكسل بالضبط، خلفية بيضاء نقية (255) |
| **التسمية التلقائية** | من ملف الإكسل: `10012345_حبه.webp`، والإضافية `-1`، `-2` |
| **الوحدات العربية** | تُكتب حرفيًا كما في الإكسل (حبه/كيس/كرتون) بلا تلف |
| **طمس التواريخ** | يخفي 97% من النص، وامتزاج اللون بفرق 1.1/255 مع الجوار |
| **حماية جدول التغذية** | أرقام التغذية والباركود **لا تُطمس أبدًا** |
| **قراءة جدول التغذية** | OCR للقيم، وإعادة رسمها بتصميم عربي قياسي |
| **الضبط الجماعي** | 8 صور في 2.7 ثانية بالتوازي |
| **استئناف العمل** | بعد إغلاق البرنامج: الموضع والمرحلة والصور المعتمدة تُستعاد |
| **WebP بلا فقدان** | مُثبت بمقارنة البكسل |

حسّنت طمس التواريخ في هذه الجلسة تحسينًا جوهريًا:

| المرحلة | قبل | بعد | التحسن |

**لا تراجع في الجودة**: نفس المناطق تُكتشف وتُطمس بنفس الدقة.

## 7. الأمان والخصوصية

- **لا مفتاح خاص في المستودع**: تحققت بـ `git ls-files` أن لا ملف أسرار
  ولا نموذج مُتتبع.
- **المثبّت يحمي بيانات الترخيص** عند الإزالة، فلا يمكن تجديد الفترة
  التجريبية بإعادة التثبيت.
- **مثبّت المالك يحمي شفرة المالك**: لا يحذفها عند الإزالة، ويحذّر
  قبل أي عملية قد تمسّها.
- **اتفاقية إلزامية** بمربع موافقة صريح على عدم الاسترداد.
- **فحوص التوافق**: ويندوز 10 وما بعده، 64-بت فقط.
- **إغلاق آمن**: أصلحت في هذه الجلسة عيبًا كان يدمّر خيوط المعالجة وهي
  تعمل عند الإغلاق — وهو ما قد يُنهي البرنامج فجأة أثناء معالجة دفعة.
