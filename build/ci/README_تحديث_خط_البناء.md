# تفعيل خط البناء الآلي وبناء المُثبِّت

## المشكلة التي يحلّها هذا الملف

خط البناء المُفعَّل على المستودع كان للإصدار **2.0.0**، بينما المشروع
وصل **2.9.5**. لذلك كان كل بناء آلي يُنتج مُثبِّتًا قديمًا بتسعة
إصدارات، وهو مصدر شكوى «السيتب يدخل بنسخة قديمة».

سبب بقاء الوضع: GitHub يمنع تطبيقات الأتمتة من إنشاء أو تعديل ملفات
`.github/workflows/` بلا صلاحية `workflows` مخصّصة. الرسالة الحرفية
عند المحاولة:

> refusing to allow a GitHub App to create or update workflow
> `.github/workflows/build-windows.yml` without `workflows` permission

فالنقل يجب أن يجري برمز المالك نفسه، ولا مفرّ من خطوة واحدة يدوية.

## التفعيل — أمر واحد

من جذر المشروع على جهازك:

```bash
git pull
bash tools/فعّل_خط_البناء.sh
```

السكربت يؤدي أربعة أعمال: يؤرشف خط البناء القديم في `build/ci/`،
وينقل خط 2.9.5 إلى مساره المُفعَّل، ويُبطل خط بناء المالك القديم
(لأنه يعمل عند كل دفعة ويستهلك دقائق بلا طلب، وبرنامج المالك صار
يُبنى داخل الخط الجديد)، ثم يدفع التغييرات.

على ويندوز بلا Git Bash، البديل اليدوي:

```
copy build\ci\build-windows-295.yml .github\workflows\build-windows.yml
del .github\workflows\build-owner-studio.yml
git add -A .github/workflows
git commit -m "تفعيل خط بناء 2.9.5"
git push
```

## التشغيل والحصول على السيتب

بعد التفعيل، من صفحة **Actions** في المستودع: اختر «بناء مُثبِّت
ويندوز 2.9.5» ثم `Run workflow`. الخط لا يعمل تلقائيًا عند الدفع
بقصد — البناء يستغرق نحو 40 دقيقة وتُحسب دقائق ويندوز بمعامل ضِعف،
فتشغيله عند كل تعديل إهدار.

| المُدخل | الافتراضي | متى تغيّره |
|---|---|---|
| `full_tests` | معطّل (6 ملفات حرجة) | فعّله قبل إصدار نهائي: 48 ملفًا، +4 دقائق |
| `include_owner` | مفعّل | عطّله إن أردت مُثبِّت المستخدم وحده أسرع |

الناتج في قسم **Artifacts** أسفل صفحة التشغيل:

| المخرَج | المحتوى |
|---|---|
| `Setup-User-2.9.5` | مُثبِّت المستخدم + بصمة SHA-256 |
| `Setup-Owner-2.9.5-CONFIDENTIAL` | مُثبِّت المالك — **سرّي، لا يُوزَّع** |
| `build-logs` | يظهر عند الفشل فقط، فيه سبب التوقف |

للتحقق من سلامة التنزيل، قارن البصمة بالملف المرافق:

```powershell
Get-FileHash AhmedAlFaifiMarketImageStudio-Setup-2.9.5.exe -Algorithm SHA256
```

## سرّ المالك

`owner_secrets.json` لا يُرفع للمستودع أبدًا. لتضمينه في البناء،
أضفه سرًّا باسم `OWNER_SECRETS_JSON` من
`Settings > Secrets and variables > Actions`، بمحتوى الملف كما هو.

بغيره يكتمل البناء لكن مع تحذير: مفاتيح التنشيط التي يولّدها هذا
البناء **لن تتوافق** مع المفاتيح التي أصدرتها سابقًا، لأن الشفرة
مختلفة. لذا إضافته مهمة إن كان لديك عملاء نشطون.

## ما أُصلح في خط البناء الجديد

| العلّة في 2.0.0 | الأثر | الإصلاح |
|---|---|---|
| نماذج تُنزَّل إلى `resources/models/` | مسار مهجور؛ الـ`spec` يقرأ من `engine_v2/models` فيفشل | `tools/fetch_models.py` ينزّل للمسار الصحيح |
| التحقق بالحجم فقط | ملف مقطوع أو مبدَّل يمرّ ثم يُنفَّذ في onnxruntime | تحقق بـ SHA-256 مع استبدال تلقائي |
| قائمة تبعيات يدوية موازية | أسقطت `xlrd` و`qrcode` و`segno`؛ وأضافت مكتبتين غير مستخدمتين | التركيب من `requirements.txt` مصدرًا وحيدًا |
| لا فحص مسبق | الفشل يظهر بعد 20 دقيقة برسالة غامضة | `verify_spec_discovery.py` قبل التحزيم |
| 4 ملفات اختبار | تغطية ضيقة | 6 حرجة، أو 48 بخيار `full_tests` |
| يعمل على كل `push` | إهدار دقائق ومُثبِّتات لا تُطلب | تشغيل يدوي فقط |
| لا بصمة للمخرَج | لا سبيل للتحقق من سلامة التنزيل | بصمة SHA-256 مرافقة |

## البناء على جهازك بدل السحابة

يستلزم Python 3.11+ و[NSIS](https://nsis.sourceforge.io) في `PATH`:

```
build\windows\ابنِ_المثبت.bat
```
